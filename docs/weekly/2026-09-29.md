# 青禾项目更新周报
> 周期：2026年9月28日—10月4日（截至9月29日）  
> 范围：原 main 本周提交，以及 codex/market-planning-shelves、codex/area-management-shelf-navigation 的本周开发成果。

## 一、本周概况

本周推进了两条工作线：原 main 增加原生微信小程序及连接优化；开发分支完善周期餐食规划、采购计量、动态商品目录与模型切换，并重构卖场设施和精确取货导航。本次将两条工作线合并到 main，保留原有小程序代码与开发历史。

当前交付属于可继续验收的开发版本，尚不能等同于正式商用或小程序功能已全面对齐。

## 二、原 main 的本周更新

### 原生微信小程序
- 新增导购、商品、地图、购物清单、菜谱、超市端、连接设置，共7个原生页面。
- 通过同一 Node.js 后端访问商品、导购、图片识别与价格建议；打包复用预算、清单和导航等共享逻辑。
- 增加小程序构建脚本、开发者工具辅助脚本、Windows 一键启动入口及导入说明。
- 小程序使用手机键盘提供的语音输入能力；未新增独立录音转文字服务。
- 清单和对话保存在当前微信设备，与浏览器数据不自动同步。

### 连接体验
- “保存并连接”的检查超时调整为6秒，区分等待超时、连接被拒绝和域名校验错误。
- 启动脚本提供手机连接地址二维码，小程序可扫码填写后端地址。
- 增加连接错误、扫码流程及共享业务的测试代码；本次合并未重新运行这些测试或真机验收。

## 三、开发分支的本周更新

### 1. 餐食规划与采购计量
- 由单次搭配扩展为周期规划，支持1—14天、每天1—4餐；“一周”默认三餐。
- 将每餐与菜品分开，模型生成多道菜及食材的克、毫升或个数需求，再匹配门店商品。
- 全周期汇总消耗量，扣除已有量，再根据商品净含量计算整包装数量，处理“每餐用油被当作整瓶”的问题。
- 油、盐、糖、生抽、老抽、醋、料酒默认家中已有；用户明确缺少时才加入采购。叉烧酱、红腐乳、玫瑰露酒等特色调料不默认已有。
- 未匹配、缺货或无法换算的食材保留展示；价格不完整时只说明本店可购部分，避免给出完整预算已满足的结论。
- 拆分计划新增金额、原清单金额和合并总额，提供逐项用量与计算依据。
- 模型输出不完整或不可用时明确退回首日示例，不将降级结果称为完整周计划。

### 2. 商品目录与模型设置
- 食品、非食品分类以及物理区域、陈列设施分别管理，支持新增、编辑与停用分类等操作。
- 补充常见食品、基础与特色调味品、部分非食品演示商品；新增结构化包装净含量，保留既有商品价格和库存。
- Web 页面增加统一模型选择，对话、餐食规划与图片识别共用所选模型；服务端保存设置，后续请求生效。
- 提供用户指定的五个 Gemini 模型选项；切换本身不发起模型调用。各模型 ID 的实际可用性与账号权限未逐一联网验证。

### 3. 卖场布局、设施和取货导航
- 参考常规网格卖场和公开门店陈列关系，新增主通道、横向通道、中央货架排、入口缓冲区、收银与服务设施。
- 分别表示双面货架、生鲜岛台、展示台、熟食服务柜台、活鲜池和冷藏柜。
- 区域改为可进入的地面范围；路径绕开实体占地、柜台操作带和固定设施。
- 商品位置包含设施编号、陈列侧面和层位；地图可查看侧面、从高到低查看各层商品，并导航到相应取货点。
- 修复旧示例商品编号为 A-02、D-03 等，却统一关联各区 01 货架的问题。
- 后台支持设施类型、占地、层数及侧面到达点配置，并增加边界、重叠、主通道占用和商品位置有效性校验。
- 默认布局迁移前将旧区域、货架、商品快照存入 SQLite 的 layout_migrations；自定义区域与已配置设施按兼容规则保留。
- 新增 LAYOUT.md，记录布局参考、设计范围和迁移说明；该地图仍为虚拟示例，不是实测室内定位系统。

## 五、当前待办与下周建议

1. **小程序与新模型对齐**：小程序当前仍使用静态分类及旧区域地图；需同步动态目录、设施占地、侧面/层位、统一模型设置与新版采购展示。构建成功不代表这部分界面适配已完成。
2. **用户实际验收**：新增区域与设施、修改商品陈列位置、按清单多站导航，以及一周规划的餐食质量、用量和金额解释。
3. **真实模型可用性**：在额度允许且用户同意时，验证完整周计划及不同模型响应；不以模拟响应代替实际生成效果。
4. **价格数据扩展**：山姆等零售报价接入仍暂缓，现阶段保留新发地查询；不宣称已获得普遍市场零售价。
5. **发布准备**：正式小程序上线仍需公网 HTTPS 后端、合法域名配置、账号权限与平台审核；目前未提交微信审核。
