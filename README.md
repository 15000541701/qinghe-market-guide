# 青禾 · 虚拟超市导购智能体

React + TypeScript + Node.js 网页应用，顾客端与超市端可切换。适合课程演示和后续开发，支持电脑、手机浏览器。

## 启动

需要 Node.js **22.13 或更新版本**（本项目在 Node.js 24 下验证）。

```powershell
npm.cmd install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 用编辑器打开 .env，填写下方模型配置
npm.cmd run build
npm.cmd start
```

打开 **http://127.0.0.1:3001**。Windows 也可以双击根目录 `启动青禾.cmd`，脚本会检查依赖、构建并启动服务。

开发模式：`npm.cmd run dev`，打开 http://127.0.0.1:5173。修改环境变量后请重新启动后端进程。

## 大模型 API 环境变量

项目根目录 `.env`：

```dotenv
AI_BASE_URL=https://你的服务商地址/v1
AI_API_KEY=你的密钥
AI_MODEL=你的模型名称
```

接口需要兼容 **Chat Completions**（后端会向 `${AI_BASE_URL}/chat/completions` 发送请求）。不必手动拼接这个后缀，已填写完整后缀也能识别。

例如使用通义千问兼容接口：

```dotenv
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_API_KEY=填写你自己的密钥
AI_MODEL=qwen-vl-plus
```

请以服务商控制台里对你的账户开放的模型为准。**图片识别必须使用支持 `image_url` 输入的视觉模型**。如果同一服务商使用不同的对话与视觉模型，可额外设置 `AI_VISION_MODEL`，留空时沿用 `AI_MODEL`。`AI_BASE_URL`、`AI_API_KEY` 仍共用。

密钥只保留在服务端 `.env` 中，不要使用 `VITE_` 前缀。`.env` 已被 `.gitignore` 排除，不要提交到仓库。应用不会下载本地模型。可运行 `npm.cmd run check:ai` 检查实际连接：会发送一条导购查询和一张项目自带的菠菜示例图片，成功后输出识别结果，不显示密钥。

未配置 API 时，文字查询可使用规则导购；图片识别会提示配置方法。上传图像先去除元数据、缩放并转换为 JPEG，再发送至配置的模型服务商。上传文件保存在本机 `data/uploads/`。

## 功能

- **顾客端**：中文自然语言查询、商品类别与价格筛选、上下文续问、图片找货、语音输入、分区地图、购物清单、商品排序、单站/多站路线与模拟到达。
- **课程演示采购助手**：支持“2 人、50 元、想吃鱼和绿叶菜、家中有葱姜”的整餐搭配，展示菜谱、参考做法、每项购买量和整单预算。可续问换便宜方案、改预算、补充家中已有食材、排除不吃的食材。
- **对话操作**：可说“把菠菜 750 克加入清单”“移除菠菜”“油盐也有，确认清单”“撤销上一步”“按清单规划路线”“去下一站”。执行后给出实际操作结果。清单操作保留最多 10 步撤销记录（当前页面会话）。
- **整单金额**：预算计算包含原有待购清单，重复确认不会重复添加；称重生鲜按预计重量计价，包装商品按整份购买。清单可按 100g 调整示例称重商品，数量会保存在当前浏览器。实际结算以门店称重为准。
- **采购条件**：油盐等调味未确认时不假定家里有；一键按钮会明确确认备料后再加入。没货、份量不够或超预算时展示原因，禁止直接合并方案。主食默认不包含，可说“也要买米”；整袋米按整袋价格计算。
- **超市端**：图片识别候选商品及分区、自动填写分区、人工纠正、历史价格参考、按需查询新发地批发行情、文字/语音改价、上架与编辑、库存搜索。
- **数据保存**：商品与价格历史保存到 SQLite 数据库 `data/market.sqlite`；购物清单保存到当前浏览器 localStorage。第一次启动会初始化 24 件演示商品。
- **定价依据**：同商品近 30 天价格中位数占 70%，7 天内参考价占 30%；只有一个有效来源时使用该来源；两者都没有时要求手动输入。必须对齐计价单位。建议区间为建议价 ±10%，不是统计置信区间。
- **单位变更**：旧价格记录会保留原单位，但不参与新单位的建议价；旧单位的市场参考价会失效，需重新填写。
- **新发地行情**：在价格建议区点击“查询新发地行情”才联网，每次点击重新获取，无定时任务。根据通用品名查询，展示本次返回记录中最新日期的报价，保留产地、规格、原单位、最低价、均价、最高价及发布日期；多条报价由工作人员选择。
- **批发到零售**：支持斤、公斤、克等明确单位换算；不猜测箱、盒规格和每枚鸡蛋重量。零售参考＝换算后的批发均价 ×（1＋加价率）。默认 30% 仅为可调整的试算参数，不是实际毛利率，未另计运输损耗。参考价再按现有历史权重参与建议。查询与计算不会覆盖最终售价；采纳并保存后才生效。
- **行情追溯**：保存商品时留存选中的原始报价、来源链接、查询时间、换算单位和加价率。再次查询会请求新数据；过期、空结果或连接失败都有明确提示，不伪造或回填演示行情。
- **导航**：BFS 搜索避开货架的通道路径；多个分区去重后按就近顺序访问。每格按 2 米估算，约 60 米/分钟。位置由用户设置，没有真实室内定位。
- **API 失败处理**：对话自动退回规则匹配；图片识别显示可操作错误，并保留超市端手动录入能力。

推荐体验：

1. 顾客端输入“推荐 10 元以内的绿叶蔬菜”，续问“只要五元以下的”。
2. 将商品加入清单，点击“带我去”，或在清单中“规划采购路线”。
3. 切到超市端，编辑已有商品、采纳建议价或手动输入价格后保存，再切回顾客端查看同步。
4. 配置视觉 API 后，在任一端上传商品图片体验自动分区。
5. 超市端编辑“鲜嫩菠菜”，点击“查询新发地行情”，选择对应产地和规格的报价，调整试算加价率后“用所选报价计算建议”，核对后采纳并保存。

新发地查询不使用大模型、不需要额外 API 密钥。数据来自 [北京新发地价格行情](http://www.xinfadi.com.cn/priceDetail.html)网页使用的 `POST /getPriceData.html`；当前可用入口为 HTTP。该网站接口不是有稳定性承诺的商业 API，查询超时或结构变化时可继续手动录价。默认单次最多读取 20 条记录，并保留其中最新日期；同日多规格报价不是全国或当地零售价平均数。

语音使用浏览器 Web Speech API，需要浏览器支持、麦克风权限以及相关语音服务可用；建议在 Chrome 或 Edge 的 localhost / HTTPS 页面体验。手机远程访问 HTTP 地址通常无法使用麦克风。语音服务可能由浏览器联网提供。

## 校验

```powershell
npm.cmd test
npm.cmd run build
# 启动应用后（本机安装 Chrome）：
npm.cmd run test:e2e
# 启动应用后，包含实际新发地查询与页面验证：
npm.cmd run test:market
# 含实际模型调用的课程演示完整流程：
npm.cmd run test:meal
```

单元测试覆盖预算筛选、续问、鱼类与绿叶菜区分、定价时效和路径避障；端到端测试覆盖主要顾客流程和超市端建议价。`tests/api.mjs` 使用本地模拟模型接口、独立测试数据库验证多模态请求格式、错误处理和持久化：`node tests/api.mjs`。

## 项目结构

```text
src/            React 页面、地图、对话与商品录入
shared/         商品类型、示例目录、筛选、定价与路线算法
server/         Express API、模型调用、SQLite 数据层
public/images/  本地展示图片与来源记录
tests/          业务逻辑、API 与浏览器验证
data/           首次运行生成的数据库与上传文件（忽略提交）
```

初始商品、历史售价、初始参考价和门店地图均为演示数据；**新发地查询返回的是实际发布的批发行情**，单独标注来源与日期。图片来自 Unsplash 与 Wikimedia Commons，仅供展示，逐文件来源在 `public/images/*.source.json`。本版本是本机演示系统，角色切换不提供登录鉴权；默认仅监听 127.0.0.1。若要部署为多人真实门店服务，需要添加身份鉴权、权限控制及真实门店数据。

## 课程展示

按 [DEMO.md](DEMO.md) 的顺序演示完整采购过程。菜谱库在 `shared/recipes.ts` 中维护，当前 9 道菜谱使用示例商品 ID；新增菜谱需要维护对应食材映射。大模型只帮助提取需求，金额、库存、预算、清单动作和路线均由程序校验。接口暂不可用时会明确退回本地规则，展示仍可继续。

“本次处理过程”展示已完成的业务步骤，不是模型内部推理。食谱用于演示家常采购。
