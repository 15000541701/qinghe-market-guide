# 青禾 · 虚拟超市导购智能体

React + TypeScript + Node.js 网页应用，顾客端与超市端可切换。适合课程演示和后续开发，支持电脑、手机浏览器。

现已提供微信原生小程序版，使用同一后端。双击 **启动微信小程序.cmd** 可构建小程序、启动后端并打开开发者工具。导入、真机连接与测试方法见 [MINIPROGRAM.md](MINIPROGRAM.md)。

## 启动

需要 Node.js **22.13 或更新版本**（本轮在 Node.js 26 下验证；启用代理时需要 Node.js 26）。

```powershell
npm.cmd install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 用编辑器打开 .env，填写下方模型配置
npm.cmd run catalog:samsclub:images -- --download
npm.cmd run build
npm.cmd start
```

打开 **http://127.0.0.1:3001**。Windows 也可以双击根目录 `启动青禾.cmd`，脚本会检查依赖、构建并启动服务。

开发模式：`npm.cmd run dev`，打开 http://127.0.0.1:5173。修改环境变量后请重新启动后端进程。

当前目录为 1,867 件 Sam’s Club US 商品，包含 12,963 张图库图片的来源、介绍、规格及带门店/渠道/时间的报价。约 3.3 GB 图片保留在本地、忽略 Git；新克隆需要执行上面的恢复命令，已有完整图片时无需重复下载。详情见 [批量采集与恢复说明](SAMSCLUB-BULK.md)。全新数据库从 `shared/samsclub-layout.json` 初始化已验证布局，已有门店的布局、人工价格和库存保持不变。

## 大模型 API 环境变量

项目目录 `.env` 支持分别保存 Gemini 和 DeepSeek 的服务端配置：

```dotenv
# 默认服务商：gemini 或 deepseek
AI_PROVIDER=deepseek

# 保留原来的 Gemini Chat Completions 兼容接口
GEMINI_BASE_URL=你的原接口地址
GEMINI_API_KEY=你的Gemini密钥
GEMINI_MODEL=gemini-3.1-flash-lite-preview

DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_MODEL=deepseek-flash
```

在页面“模型设置”中先选择服务商，再选择该服务商的模型并保存。地址、密钥随服务商成组切换，不会混用两家的凭据。界面保存的服务商与模型保存在 `data/model-settings.json`（或 `DATA_DIR` 对应目录），重启后仍然生效；`.env` 的 `AI_PROVIDER` 和各服务商 `*_MODEL` 用于尚未保存设置时的默认选择。修改地址或密钥后需要重启后端。

首次升级时，旧版仅含 `model` 的保存文件会识别所属服务商。如果 `.env` 明确配置了不同的 `AI_PROVIDER`，首次读取采用该服务商的默认模型；之后通过界面保存的设置优先。切回 Gemini 时可在下拉框选择原模型。

旧版 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 仍兼容：未定义 `GEMINI_BASE_URL` 和 `GEMINI_API_KEY` 时，旧地址和密钥作为 Gemini 分组使用，旧模型作为 Gemini 默认模型。定义新 Gemini 地址或密钥中的任意一个后，必须完整填写这一组，避免混用旧凭据。旧版接入的其他 Chat Completions 服务也可以继续沿用旧配置；界面预设模型针对 Gemini 和 DeepSeek。

接口需要兼容 **Chat Completions**，后端向 `${BASE_URL}/chat/completions` 发送请求。地址无需手动拼接后缀，填写完整后缀也能识别。Gemini 分组继续使用你原来可用的兼容接口地址，不会自动更换为其他端点。

DeepSeek 默认使用 `deepseek-flash`，文字导购、餐食规划和图片识别共用所选模型。`deepseek-v4-pro` 仅支持文字，选用它时图片请求会在本地提示切换模型。DeepSeek 请求关闭思考模式，并要求 JSON 输出；Gemini 保留现有请求格式。模型能力以 [DeepSeek 官方文档](https://api-docs.deepseek.com/quick_start/pricing/) 为准。

如果本机依赖网络代理，在 `.env` 显式填写 `AI_PROXY_URL=http://127.0.0.1:7890`（端口应以你的代理软件为准）。macOS 的系统代理不会自动被 Node fetch 使用。启用该选项时使用 Node.js 26 或更新版本；它为后端出站 HTTP(S) 请求配置代理，本机回环接口始终直连。留空时不改变网络行为。修改后需要重启后端，且代理软件必须保持运行。聊天中的失败提示会区分连接超时、密钥权限、余额不足和限流。

当前统一模型设置**不读取 `AI_VISION_MODEL`**。如需文字和图片分别使用不同服务商，需要另行扩展配置。

密钥只保留在服务端 `.env` 中，不要使用 `VITE_` 前缀，也不要发到聊天或提交到仓库。`.env` 已被 `.gitignore` 排除。设置接口只返回服务商和模型，不返回地址或密钥；保存设置不发送模型请求，也不检查账户权限或余额。

未配置所选服务商的密钥时，文字查询可使用规则导购；图片识别会提示配置方法。上传图像先去除元数据、缩放并转换为 JPEG，再发送至所选模型服务商。上传文件保存在本机 `data/uploads/`。

本项目当前只运行本地构建、商品解析和基础业务检查，不运行模型测试流程。模型服务配置与实际可用性分开记录；`npm run check:ai` 会调用真实模型并消耗额度，不运行。

## 功能

- **顾客端**：中文自然语言查询、商品类别与价格筛选、上下文续问、图片找货、语音输入、分区地图、购物清单、商品排序、单站/多站路线与模拟到达。
- **动态目录与门店位置**：超市端可新增、改名、停用食品/非食品分类；分类可映射到独立的物理分区。分区与货架坐标可管理，商品选择具体货架。分类及位置保存在 SQLite，旧商品与历史记录保持兼容。地图路线按货架通道点规划；缺少位置或不可达时会明确提示。虚拟地图不提供真实室内定位。
- **周期采购计划**：可解析 1–14 天、每天 1–4 餐；“一周”默认每天三餐。目前只规划适合美国山姆商品的西式餐食。程序整理完整可用食品名录（商品 ID、英文原名、规格、价格、加工状态）发给模型，模型用中文说明菜谱、用英文食材名和商品 ID 引用名录，输出两人份食用量。支持三明治、意面、沙拉、烤鱼等；混合餐可覆盖多个餐食角色，不强制三道独立菜。模型不可用时按当前可购商品生成完整周期的西式模板方案，明确提示菜式可能重复。
- **对话操作**：可说“把菠菜 750 克加入清单”“移除菠菜”“油盐也有，确认清单”“撤销上一步”“按清单规划路线”“去下一站”。执行后给出实际操作结果。清单操作保留最多 10 步撤销记录（当前页面会话）。
- **整单金额**：全周期先汇总食材需求、扣除已购量和原清单数量，再依据结构化 SKU 净含量换算整包装数。称重生鲜按预计重量计价，1.8L 食用油等包装商品按瓶购买。重复确认不会重复添加；价格、库存和预算由程序校验。
- **家庭常备项**：食用油、盐默认家中已有，不计入采购；做法仍展示用量。顾客可在菜谱面板编辑常备项，设置保存在当前浏览器。明确表示“家里没有油”后，食用油按全周毫升量匹配包装；大蒜、黑胡椒、其他香料和酱料等不默认已有。
- **商品匹配与缺价**：商品检索与匹配使用英文原名；中文需求先映射为英文食材名。区分生鲜原料与熟食、裹粉食品、蘸酱等复合食品，不自动按名称包含关系替换。规格未知、零净含量、已识别的多包装净含量错误及非食品不进入模型餐食名录；逐项标明本店暂无或规格无法换算。无匹配商品、缺货或未知价食材保留在菜谱中并阻止完整预算结论；这时只显示“本店可购部分”与未计价项目数，不声称满足预算。
- **整单预算**：计划采购新增金额、原购物清单金额和合并待购金额分开展示。预算包含原清单其他商品；购物清单可按 100g 调整示例称重商品，数量会保存在当前浏览器。实际结算以门店称重为准。
- **超市端**：图片识别候选商品及分区、自动填写分区、人工纠正、历史价格参考、按需查询新发地批发行情、文字/语音改价、上架与编辑、库存搜索。
- **真实 SKU 商品库**：当前使用 Sam’s Club US 公开详情，以 Item # 去重，区分详情页编号、门店和渠道报价。商品卡片点击进入详情页后可翻看完整图库、介绍和规格。旧目录默认不再补充；导入不覆盖人工改价与库存。页面库存 100 是演示库存，报价为来源页面参考价，实际称重金额以结算为准。
- **SKU 批量与陈列管理（Web）**：超市端支持CSV/JSON导入、预检、原子保存和导出；可将商品拖到指定设施的侧面与层位。扩展纸品、宠物、日化、零食冷冻区域，增加卧式冷冻柜与服饰挂架。字段、来源和操作说明见 [SKU-MANAGEMENT.md](SKU-MANAGEMENT.md)。
- **定价依据**：同商品近 30 天价格中位数占 70%，7 天内参考价占 30%；只有一个有效来源时使用该来源；两者都没有时要求手动输入。必须对齐计价单位。建议区间为建议价 ±10%，不是统计置信区间。
- **单位变更**：旧价格记录会保留原单位，但不参与新单位的建议价；旧单位的市场参考价会失效，需重新填写。
- **新发地行情**：在价格建议区点击“查询新发地行情”才联网，每次点击重新获取，无定时任务。根据通用品名查询，展示本次返回记录中最新日期的报价，保留产地、规格、原单位、最低价、均价、最高价及发布日期；多条报价由工作人员选择。
- **批发到零售**：支持斤、公斤、克等明确单位换算；不猜测箱、盒规格和每枚鸡蛋重量。零售参考＝换算后的批发均价 ×（1＋加价率）。默认 30% 仅为可调整的试算参数，不是实际毛利率，未另计运输损耗。参考价再按现有历史权重参与建议。查询与计算不会覆盖最终售价；采纳并保存后才生效。
- **行情追溯**：保存商品时留存选中的原始报价、来源链接、查询时间、换算单位和加价率。再次查询会请求新数据；过期、空结果或连接失败都有明确提示，不伪造或回填演示行情。
- **导航**：区域是可进入的地面范围，BFS 避开陈列设施、服务柜台操作带及固定设施；路线终点为商品所在陈列面的取货点，多件商品按设施与侧面去重。每格按 2 米估算，约 60 米/分钟。当前位置由用户手动选择，没有真实室内定位。
- **API 失败处理**：对话自动退回规则匹配；图片识别显示可操作错误，并保留超市端手动录入能力。

推荐体验：

1. 顾客端输入“推荐 10 元以内的绿叶蔬菜”，续问“只要五元以下的”。
2. 将商品加入清单，点击“带我去”，或在清单中“规划采购路线”。
3. 切到超市端，编辑已有商品、采纳建议价或手动输入价格后保存，再切回顾客端查看同步。
4. 配置视觉 API 后，在任一端上传商品图片体验自动分区。
5. 超市端编辑“鲜嫩菠菜”，点击“查询新发地行情”，选择对应产地和规格的报价，调整试算加价率后“用所选报价计算建议”，核对后采纳并保存。

陈列导航：在顾客端“店内地图”点击货架、岛台、熟食柜台或活鲜池，可查看侧面与商品层位；商品“带我去”使用对应陈列面的取货点。区域内可以行走，路线绕开设施实体。示例布局、参考来源与旧数据迁移说明见 [LAYOUT.md](LAYOUT.md)。旧布局迁移前会保存数据库快照；未配置占地的自定义旧点位提示在后台补充。

新发地查询不使用大模型、不需要额外 API 密钥。数据来自 [北京新发地价格行情](http://www.xinfadi.com.cn/priceDetail.html)网页使用的 `POST /getPriceData.html`；当前可用入口为 HTTP。该网站接口不是有稳定性承诺的商业 API，查询超时或结构变化时可继续手动录价。默认单次最多读取 20 条记录，并保留其中最新日期；同日多规格报价不是全国或当地零售价平均数。

语音使用浏览器 Web Speech API，需要浏览器支持、麦克风权限以及相关语音服务可用；建议在 Chrome 或 Edge 的 localhost / HTTPS 页面体验。手机远程访问 HTTP 地址通常无法使用麦克风。语音服务可能由浏览器联网提供。

## 项目结构

```text
src/            React 页面、地图、对话与商品录入
shared/         商品类型、示例目录、筛选、定价与路线算法
server/         Express API、模型调用、SQLite 数据层
public/images/  本地展示图片与来源记录
tests/          业务逻辑、API 与浏览器验证
data/           首次运行生成的数据库与上传文件（忽略提交）
```

山姆商品名称、图库和报价来自公开页面，价格保留采集上下文，库存与门店地图用于本机演示；**新发地查询返回的是实际发布的批发行情**，单独标注来源与日期。周期计划通过整理后的美国山姆英文食品名录生成西式餐食；商品 ID、状态、食用单位、忌口、餐次与搭配由程序校验。金额与整包装采购数由程序计算；本店缺货或规格无法换算时不会宣称预算完整。模型不可用时使用西式模板，可有重复菜式。图库来源保存在 `shared/samsclub-catalog.json`，旧演示图的来源在 `public/images/*.source.json`。本版本是本机演示系统，角色切换不提供登录鉴权；默认仅监听 127.0.0.1。若要部署为多人真实门店服务，需要添加身份鉴权、权限控制及真实门店数据。

## 课程展示

按 [DEMO.md](DEMO.md) 的顺序演示完整采购过程。`shared/recipes.ts` 保存西式本地模板；`shared/meal-catalog.ts` 整理可用英文食品名录；单日与周期计划均可由大模型按该名录生成菜名、做法和每道菜食材用量，生成的计划连同上下文回传以便重复计算和确认。金额、库存、包装采购量、清单动作和路线由程序校验。模型接口暂不可用时按本店可购商品提供完整周期模板，并说明菜式可能重复。旧版中式会话会失效并按西式规则重建。

“本次处理过程”展示已完成的业务步骤，不是模型内部推理。食谱用于演示美国山姆商品的西式餐食采购。
